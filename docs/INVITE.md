# 邀请：后台创建 → 生成链接 → 好友收到 → 两边聊起来

> 状态：**需求已定，开工中**。这篇是唯一口径，改需求先改这里。

## 一句话

牛马在后台填一份邀请（**日期 / 时间 / 地点 / 做什么**）→ 点创建 → 拿到一条链接 →
复制发给好友 → 好友点开看一段**拆信式的精美动画** → 接受或婉拒 →
**然后两个人在里面互相留言**。

> ⭐ **最重要的其实是最后那步。** 它不是一张看完就扔的请柬，
> 而是**一个约会协调器**：定下来之后还要商量「几点到」「要不要带伞」「我想吃那家」。
> 毕竟是约会，来回说话才是主体。

它和「申请」是**两条独立的线**：

| | 谁发起 | 好友要做什么 | 之后 |
| --- | --- | --- | --- |
| **申请**（已有） | **好友** | 选身份 → 选时间 → 提交 | 牛马审批，单向 |
| **邀请**（新增） | **牛马** | 点开看 → 接受 / 婉拒 | **两边可以来回留言** |

## 一、后台那一侧

### 创建 / 编辑邀请

**所有文案字段都能改**（用后台的人熟悉这套系统，自由度给够），
每个字段都带**已经确认好的默认值**，不改也能直接发。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| 身份 | 好兄弟 | 四选一。决定**整套皮 + 全部默认文案** |
| 邀请谁 | 空 | 填了就显示「小美，…」；留空是通用链接，谁点都能看 |
| **日期** | — | **日期选择器**（能排序、能判断过期） |
| **时间** | — | **自由文字**，如「晚上七点半」（邀请往往不是整时段） |
| 地点 | — | 如「楼下那家火锅」 |
| 做什么 | — | 如「吃火锅，然后江边走走」 |
| 标题 | 按身份预设 | |
| 开场白 | 按身份预设 | 支持 `{name}` 占位符 |
| 正文 | 按身份预设 | 可以多行 |
| 落款 | 按身份预设 | |
| **不允许拒绝** | 不勾 | **创建时勾选**。开了就没有婉拒按钮 —— 小人会把它抓走扔掉，见下 |

**列表**：待回应 / 已接受 / 已婉拒。
每条能**复制链接**、**编辑**、**删除**，并显示**对方什么时候回应的**。

### 后台能看到对话，也能回话

这是这次的关键补充 ✓ 后台打开一条邀请，除了看状态，还能：

- 看到好友说了什么、什么时候说的
- **直接回一句** —— 和申请的「审批意见」不同，这里是**来往的消息流**，不是单条备注

## 二、好友那一侧

### 链接

```
https://niumadate.xyz/i/<一串随机码>
```

码要**够长、猜不到**（不然谁都能翻别人的邀请）。
点开后把这串码**记进好友自己的浏览器**，以后他进「我的记录」就能翻到收到的每一份邀请。

> 代价和现在的申请一样：清缓存 / 换浏览器就丢。
> 「我的记录」里已经有现成的说明文案可以复用 —— 同一套道理，不用再解释一遍。

### 邀请页：拆信

**叙事方式定了：拆信 + 滚动**，不是一页一屏 ✓

大致顺序：

1. **火漆印章**从上方落下，盖在信封上（复用现有公章那套动画）
2. 印章淡出，**信纸缓缓展开**
3. 内容**逐段浮现**（滚动着看）：称呼 → 时间 → 地点 → 做什么
4. 最后**两个按钮弹出来**：接受**大而突出**，婉拒**小**

### 段落之间的过渡：**交给小人** ⭐

这是你点出来的想法，我很喜欢，单独记一节：

> 「可以用这个小人来过渡，或者用这个小人**费劲地拉出来**，
> 或者**飞机一样飞出去**，或者给它**压下去** ——
> 一些很灵活、很好玩、很有趣、很充满互动性的过渡动画。」

所以每一段之间的衔接不靠淡入淡出，而是**一个小人在那儿干活**：

| 过渡 | 小人做什么 |
| --- | --- |
| 进下一段 | 费劲地把下一段**拉出来** |
| 跳过去 | 抓着它**飞出去** |
| 收起来 | 一屁股**压下去** |

（具体分镜到时候逐帧对。四套身份的小人造型也跟着现有四套皮走。）

### 回应

- **接受**：按钮大、好看、突出 ✓
- **婉拒**：按钮小 ✓
- **回应之后还能改** ✓ —— 后台能看到改动历史（最新状态 + 什么时候改的）

### 「不允许拒绝」模式 ⭐

勾了这个开关之后，婉拒按钮**还在，但点不到** —— 因为会发生这些：

1. 一个**非常精美的小人**从**屏幕右边**走进来
2. 走到婉拒按钮前，**一把把它抓起来**
3. **团成团，扔出去**
4. 回过头，把接受按钮**用力拉大**
5. **坐在上面，双腿耷拉下来**
6. **指着「同意」**

> 这是整个功能里最有记忆点的一段，值得单独花时间做细。

### 聊起来

回应之后，邀请页下方变成**一个对话区**：

- 好友能发消息 ✓
- 能来回好几轮 ✓
- 显示各自说话的时间 ✓

## 三、主页面改版

现在是「先刷一下身份」四张卡。改成**两个大按钮**：

| 按钮 | 点了去哪 |
| --- | --- |
| **我要约牛马** | 进现在的选身份流程（四张卡，一步没少） |
| **我的记录** | 两块：**我提交的申请** + **我收到的邀请** |

「我的记录」= 现在的 `/mine` 扩一块「收到的邀请」，
点进某一份就能看内容、回应、继续聊。底部保留「我要约牛马」，两边互相走通。

## 四、技术方案

| 层 | 要加什么 |
| --- | --- |
| 数据库 | `invites` 表：码 / 身份 / 名字 / 日期 / 时间 / 地点 / 做什么 / 四段文案 / 不允许拒绝 / 回应状态 / 回应时间 |
| | `invite_messages` 表：邀请 id / 谁发的（主人 or 好友）/ 内容 / 时间 |
| 后端 | 后台：列表、创建、编辑、删除、回话；公开：按码取邀请、回应、留言 |
| 后台 | 邀请列表 + 编辑器 + 一键套用预设 + 复制链接 + 对话区 |
| 好友端 | `/i/<码>` 邀请页（拆信动画 + 小人过渡 + 回应 + 对话） |
| 主页 | 两个大按钮；`/mine` 加一块「收到的邀请」 |
| 预设 | 四个身份各一套邀请文案（标题 / 开场白 / 正文 / 落款） |

### 分阶段做

1. **数据层 + 接口**（邀请 CRUD、回应、留言）
2. **后台界面**（列表 + 编辑器 + 复制链接 + 对话区）
3. **好友端邀请页**（拆信动画 + 小人过渡 + 回应 + 对话）
4. **主页改版** + 「我的记录」扩一块
