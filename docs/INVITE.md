# 邀请：后台创建 → 生成链接 → 好友收到 → 两边聊起来

> 状态：**需求已定，开工中**。这篇是唯一口径，改需求先改这里。

## 一句话

牛马在后台填一份邀请（**日期 / 时间 / 地点 / 做什么**）→ 点创建 → 拿到一条链接 →
复制发给好友 → 好友点开看一段**拆信式的精美动画** → 接受或婉拒 →
**然后两个人在里面互相留言**。

> ⭐ **最重要的其实是最后那步。** 它不是一张看完就扔的请柬，
> 而是**一个约会协调器**：定下来之后还要商量「几点到」「要不要带伞」「我想吃那家」。
> 毕竟是约会，来回说话才是主体。

它和「申请」是**两条独立的线**：

| | 谁发起 | 好友要做什么 | 之后 |
| --- | --- | --- | --- |
| **申请**（已有） | **好友** | 选身份 → 选时间 → 提交 | 牛马审批，单向 |
| **邀请**（新增） | **牛马** | 点开看 → 接受 / 婉拒 | **两边可以来回留言** |

## 一、后台那一侧

### 创建 / 编辑邀请

**所有文案字段都能改**（用后台的人熟悉这套系统，自由度给够），
每个字段都带**已经确认好的默认值**，不改也能直接发。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| 身份 | 好兄弟 | 四选一。决定**整套皮 + 全部默认文案** |
| 邀请谁 | 空 | 填了就显示「小美，…」；留空是通用链接，谁点都能看 |
| **日期** | — | **日期选择器**（能排序、能判断过期） |
| **时间** | — | **自由文字**，如「晚上七点半」（邀请往往不是整时段） |
| 地点 | — | 如「楼下那家火锅」 |
| 做什么 | — | 如「吃火锅，然后江边走走」 |
| 标题 | 按身份预设 | |
| 开场白 | 按身份预设 | 支持 `{name}` 占位符 |
| 正文 | 按身份预设 | 可以多行 |
| 落款 | 按身份预设 | |
| **不允许拒绝** | 不勾 | **创建时勾选**。开了就没有婉拒按钮 —— 小人会把它抓走扔掉，见下 |

**列表**：待回应 / 已接受 / 已婉拒。
每条能**复制链接**、**编辑**、**删除**，并显示**对方什么时候回应的**。

### 后台能看到对话，也能回话

这是这次的关键补充 ✓ 后台打开一条邀请，除了看状态，还能：

- 看到好友说了什么、什么时候说的
- **直接回一句** —— 和申请的「审批意见」不同，这里是**来往的消息流**，不是单条备注

## 二、好友那一侧

### 链接

```
https://niumadate.xyz/i/<一串随机码>
```

码要**够长、猜不到**（不然谁都能翻别人的邀请）。
点开后把这串码**记进好友自己的浏览器**，以后他进「我的记录」就能翻到收到的每一份邀请。

> 代价和现在的申请一样：清缓存 / 换浏览器就丢。
> 「我的记录」里已经有现成的说明文案可以复用 —— 同一套道理，不用再解释一遍。

### ⭐ 邀请页是**独立的视觉层**，不必和现有四套皮长得一样

这一条是后来才想明白的，很重要：

> 「这个动画未必要跟之前的四个风格一模一样，因为是动画嘛，所以可以做得**更加精美**一些。」

**邀请页和填写页的处境完全不同**：

| | 填写页 / 后台 | 邀请页 |
| --- | --- | --- |
| 用几次 | **天天用**，还要填一堆东西 | **一辈子看一两次** |
| 首要目标 | 顺手、看得清、不累眼 | **好看、记得住、想截图** |
| 所以 | 克制（这也是为什么四套皮都很"收着"） | **放开了做** |

所以邀请页**不复用**现有主题的字体栈和配色，而是**另做四套视觉** ——
仍然是四套（对应四个身份），但每一套按"一次演出"的标准来，
可以用更重的材质、更细的动效、更多的层次。

**四套的「材质语言」**（每个身份一种材料，比单纯换配色更有质感）：

| 身份 | 材质 | 大致感觉 |
| --- | --- | --- |
| 好兄弟 | **牛皮纸 + 酒渍 + 深红火漆** | 粗糙、随意、兄弟之间那种不拘小节 |
| 好姐妹 | **珠光信笺 + 玫瑰金烫印 + 缎带** | 精致、有光泽、值得拍一张 |
| 好宝宝 | **奶油纸 + 会飘的云 + 糖果色** | 软、圆、字会弹一下 |
| DAD&MUM | **红头文件 + 钢印压痕 + 表格线** | 正经到好笑（内容却是家事） |

### 「精美」具体精在哪（做的时候按这个清单来）

纯 CSS + SVG，不加动画库（和项目一贯的取向一致）：

- **火漆印章盖下去时，蜡会向四周溢开** —— 这一下最出效果
- **信纸三折，一层层展开**，不是整张淡入
- **墨迹感**：标题像刚写完那样一笔一笔出现（SVG `stroke-dasharray`）
- **烫金**：贵金属渐变 + 缓慢的反光扫过
- **纸张纹理和弯曲阴影**：不是一张纯色矩形
- **少量粒子**：展开时飘几点光尘，别多，多了显廉价
- **滚动视差**：手指滑动时纸面和文字有轻微错位

### 邀请页：第一屏（背景 + 信封，就这两个主体）

| | 内容 |
| --- | --- |
| **背景** | 四套风格各自的底色 + 氛围。**信封后面不要垫任何东西**（不要卡纸、不要白纸） |
| **信封** | 直接放在背景上。信封里是一个三角形（翻盖），三角形上盖着一枚**火漆** |

- 火漆有**四种形态**，按身份走：颜色、图案、消失方式都不是同一个。
- 三角形是信封的翻盖，**最长的那条边在顶上**（后面绕它翻）。
- 屏上只有两行字：「有一封邀请」/「拆开看看？」
- 第一屏是**静止**的：它先安静地放在那儿，等好友点「轻点继续」。

### 第一屏 → 第二屏：拆信（四拍，总长约 4.3 秒）

这是整页的开场，四拍一步都不能省，而且**每一拍都要在动**（不用空等凑时长）：

**第 1 拍 · 火漆消失（四种之一）**

| 身份 | 怎么消失 |
| --- | --- |
| 好兄弟 | 原地淡掉、微微下沉。**不飞、不炸、没有花** —— 「平淡」就是他的性格 |
| 好姐妹 | 整体转开、缩小、上飘，花瓣被风斜着吹散 |
| 好宝宝 | 先「绽开」一下（放大变亮），再炸成满天转着圈的花 |
| 家人 | 从正中利落裂开，两半**垂直**落下，掉几粒渣 |

**第 2 拍 · 三角形翻盖绕最长的那条边向屏幕外翻起来**

- 平面 → 垂直于视线 → 翻到顶上去（绕顶边 rotateX：0° → -90° → -180°）
- 翻过去之后露出的**背面要和正面明显不一样** —— 不然看不出「翻过去了」
- 翻到位之后被「抬走」

**第 3 拍 · 信封向下隐藏**

滑下去，不是原地淡掉。

**第 4 拍 · 白信纸从信封口被抽出来**

- 一边往上冒、一边长大，不是整张淡入
- 最后停在「一张纸」的范围：**宽度和后面内容页的信纸对齐**，这样交接到第二屏不跳

### 内容页（第二屏起）

依次是：这一封是给你的 → 时间 → 地点 → 做什么 → 信里的话 → 正式请柬 → 回答 → 留言。
每页就是一张信纸，居中，一个字都不多。

### 内容页之间的翻页：还是那个小人在干活 ⭐

**三个出场边轮着来：左 / 右 / 上。** 每个衔接都是「两趟」：
先把旧的那页弄走，再从**同一处**把新的那页弄回来。

#### 左 / 右（拉）

- 小人从屏幕**左边**（或右边）进场，**侧对着用户**（面朝信纸，不是正面朝向观众）
- 走到信纸旁边站定 —— **这段时间信纸一动不动**（先让观众看清「他要拉了」）
- 伸出靠内那只手抓住信纸边缘，另一只手（或整个身子）往后仰，**使劲拽几下**：
  第 1 下纸几乎不动 → 第 2 下动一点 → 第 3 下才拽动。
  **这三下的顿挫是整个「费劲」的全部来源**，省了就只是「滑过去」
- 把信纸**从哪边来就拖回哪边去**（左边来的一路拖出左边屏幕）
- 小人跟着出去，然后**从同一边回来**，把**新的那一页**拖进来（右边完全镜像）

#### 上（压）

- 小人从**上边**出来，落到信纸上、**坐在上面往下压**：压扁 → 弹回 → 再压 → 压到底
- 信纸**从最底下被压出去**
- 回来方式不一样：**从上面掉一根绳子下来**，把新的那一页**拉上去**

### 最后的小巧思：「不允许拒绝」⭐

- 小人从左边走出来，**气鼓鼓**的（姿态和表情都要看得出来）
- 把「不去」按钮**揉成团** —— 这个动作要细：
  抓住 → 团起来 → 捏皱 → 变成一个纸团（**不是直接缩放**）
- 像扔东西一样**甩出去**（抛物线 + 旋转 + 淡出）
- 然后把「同意」按钮**拉大**（同样要细：先一顿，再撑开，再稳稳放大）
- 最后**坐在上面**，让好友只能选同意
- 整段 4~5 秒，每一步都要看得清

### 时长与风格（硬要求）

- 拆信 ~4.3 秒；**每次翻页 4~5 秒**
- **每个关键帧都要在动**：不用「等待」凑时长，也不靠「加载慢」制造仪式感
- 幽默、好玩、细节足 —— 目标是「网上那种用 vibe coding 做出来的漂亮顺滑的动画」
- 幽默感的来源：小人的姿态（费劲、气鼓鼓、被纸带着滑出去）+ 文案的口气

### 回应

- **接受**：按钮大、好看、突出 ✓
- **婉拒**：按钮小 ✓
- **回应之后还能改** ✓ —— 后台能看到改动历史（最新状态 + 什么时候改的）

### 「不允许拒绝」模式 ⭐

勾了这个开关之后，婉拒按钮**还在，但点不到** —— 因为会发生这些：

1. 一个**非常精美的小人**从**屏幕右边**走进来
2. 走到婉拒按钮前，**一把把它抓起来**
3. **团成团，扔出去**
4. 回过头，把接受按钮**用力拉大**
5. **坐在上面，双腿耷拉下来**
6. **指着「同意」**

> 这是整个功能里最有记忆点的一段，值得单独花时间做细。

### 聊起来

回应之后，邀请页下方变成**一个对话区**：

- 好友能发消息 ✓
- 能来回好几轮 ✓
- 显示各自说话的时间 ✓

## 三、主页面改版

现在是「先刷一下身份」四张卡。改成**两个大按钮**：

| 按钮 | 点了去哪 |
| --- | --- |
| **我要约牛马** | 进现在的选身份流程（四张卡，一步没少） |
| **我的记录** | 两块：**我提交的申请** + **我收到的邀请** |

「我的记录」= 现在的 `/mine` 扩一块「收到的邀请」，
点进某一份就能看内容、回应、继续聊。底部保留「我要约牛马」，两边互相走通。

## 四、技术方案

| 层 | 要加什么 |
| --- | --- |
| 数据库 | `invites` 表：码 / 身份 / 名字 / 日期 / 时间 / 地点 / 做什么 / 四段文案 / 不允许拒绝 / 回应状态 / 回应时间 |
| | `invite_messages` 表：邀请 id / 谁发的（主人 or 好友）/ 内容 / 时间 |
| 后端 | 后台：列表、创建、编辑、删除、回话；公开：按码取邀请、回应、留言 |
| 后台 | 邀请列表 + 编辑器 + 一键套用预设 + 复制链接 + 对话区 |
| 好友端 | `/i/<码>` 邀请页（拆信动画 + 小人过渡 + 回应 + 对话） |
| 主页 | 两个大按钮；`/mine` 加一块「收到的邀请」 |
| 预设 | 四个身份各一套邀请文案（标题 / 开场白 / 正文 / 落款） |

### 分阶段做

1. **数据层 + 接口**（邀请 CRUD、回应、留言）

3. **好友端邀请页**（拆信动画 + 小人过渡 + 回应 + 对话）
4. **主页改版** + 「我的记录」扩一块
