## 1. 项目

| 项 | 内容 |
| --- | --- |
| 名称 | **非工作时间约会审批系统** |
| 别名/内部代号 | 牛马出栏审批单 |
| 定位 | 发给好友的约会时间选择页面 + 一个极简审批后台 |
| 使用者规模 | 少量（个位数到几十人），用户端**不需要登录** |
| 语言 | 全中文 |
| 端 | **移动端优先**（好友大概率在微信内置浏览器打开） |

## 2. 形态与技术选型

| 项 | 决定 | 备注 |
| --- | --- | --- |
| 部署形态 | **纯线上**，一套代码一套产物 | 离线单文件、好友导出 JSON、后台导入 JSON **全部取消** |
| 前端 | React 19 + Vite 8 + TypeScript | SPA，客户端路由 |
| 后端 | Fastify 5 + TypeScript | 与前端同源部署，生产环境由后端托管前端静态产物 |
| 数据库 | **SQLite**（Node 内置 `node:sqlite`，无需编译原生模块） | 单文件，备份 = 拷文件 |
| 配置 | `config.json`，**运行时读取**，存在服务器上 | 后台可改，改完立刻生效，不需要重新发版 |
| 进程守护 / 域名 / HTTPS | 部署时再定（用户自行租赁云服务器） | 见 `docs/DEPLOY.md` |

## 2.5 路由划分

**填写和状态是两条独立路由**，这是硬约束：

| 路由 | 干什么 | 进去先判断 |
| --- | --- | --- |
| `/` | 入口页，选身份 | — |
| `/date/:role` | 只负责填写 | 已有**生效中**的申请 → 转到 `/status/:role` |
| `/status/:role` | 只负责展示回执 / 驳回结果 | 没有申请或已过期 → 转回 `/date/:role` |
| `/admin` | 后台 | 口令 |

> 为什么必须拆开：两件事混在一个页面里，被驳回后点「重新填一份」再选同一个身份时，
> 「最近一条是 cancelled」这个判断会把好友又弹回驳回页，形成死循环——永远填不了。
> 拆开之后，填写页只在「有生效中的申请」时才转走，cancelled 不影响它。

## 3. 用户端流程

```
打开链接（一个链接，所有人共用）
  ↓
入口页：四张身份卡片（卡片始终可见）
  ↓ 点已开启的卡片                            ↓ 点已关闭的卡片
向导式填写（**一个问题一页**，答完自动翻页）      弹出「关停文案」+ 动图 / 艺术字
  第 1 页  昵称（**好宝宝 / 父母跳过这一页，见 5.1**）
  第 2 页  日期          ← 月历，可左右切月；点一下某天就翻页
  第 3 页  时段          ← 只在所选日期上选；点一下选中，再点一下取消
            └ 支线：自己定一个时间（日期沿用上一步，只填「几点」和「干嘛」）
  第 4 页  地点
  第 5 页  见面要求 + 留言（都是自由文本，合成一页）
  第 6 页  确认 → 提交
  ↓
提交成功：「牛马正在骑马赶来的路上……」
  ↓ 再次进入（同一个设备）
仍然显示该状态，直到约会结束 / 后台修改状态 / 后台删除
```

## 5. 时间选择

**日期和时段分成两页**，各自是一道题。

- 第 2 页是**月历**：年、月各是一个**下拉栏**（可以直接跳），两侧还有 ‹ › 按钮逐月翻。
  日历上要能一眼看出「哪天值得点」：

  | 标记 | 含义 |
  | --- | --- |
  | 暖色底 | **休息日**（不在当前工作制的上班日里） |
  | 划掉 + 🔒 + 压暗 | **约不上**：这天所有时段都被工作冻住了 |
  | 灰色 | 过去的 / 超出可选范围 |
  | 细边框 | 今天 |
  | 小绿点 | 已经选过时段的 |

  底部有图例说明「休息日 / 约不上」。
  > 加这两个标记之前，工作日（全锁）和周日（全开）在日历上长得一模一样，
  > 好友得一天一天点进去试 —— 在 `overlap` 配置下要试 6 次才摸得到周日。
- 第 3 页只在**那一天**上面选时段；**点一下选中，再点一下取消**（防止选错了没法改）。
- 时段三档，边界写在 `config.json` 里可改：

  | 时段 | 默认边界 | 可选 |
  | --- | --- | --- |
  | 早上 | 06:00 – 11:00 | **不可选**（只放出来看看） |
  | 中午 | 11:00 – 17:00 | 可选（工作日可能被冻） |
  | 晚上 | 17:00 – 23:00 | 可选 |

- **可选日期范围**：从今天起未来 N 天（默认 **60 天**，可配）。默认拉到两个月，日历的切月才有意义。
- **可以多选**多个「日期 + 时段」组合：确认页有「+ 再加一个时间」，点了回到日期页再选一组。至少选一个。

### 三种「不能选」，理由不同

| 状态 | 触发条件 | 表现 |
| --- | --- | --- |
| 只放出来看看 | 时段配置里 `selectable: false`（默认只有早上） | 灰色虚线卡片，写着「😴 起不来，仅供观赏」，点了弹起床气文案 |
| 被工作冻住 | 落在工作时间内（见下） | 冰面虚线卡片，「🔒 牛马在上班」，点了弹悬浮提示 |
| **这天全锁** | 三个时段都被冻住 | 顶部弹一条醒目提示：「这天牛马全天在岗，一个时段都约不上。换一天，或者自己定一个时间」，并把「自己定一个时间」**提成主按钮** |

悬浮提示**不会赖着不走**：点页面别处会关、约 3 秒后自动关、再点同一个格子也关。
| 可选 | 其他 | 「✨ 可以约」 |

- 早上的那句吐槽文案由 `copies.morning` 配置，支持 `{name}` 占位。
- **自定义时间**：时段页有支线入口「这几个都不合适？自己定一个时间 →」。进去之后**日期沿用上一步选好的那天**，只填两栏大字输入：「几点」和「干嘛」（存成 `日期 · 几点 · 干嘛`）。可跳过。

### 工作制与冻结规则

- 默认 `lockMode: "covered"`：时段**完全落在**工作时间之内才锁。996（周一至周六 09:00–21:00）下只有「中午」被冻——符合「有些时间就是锁定的」。
- 备选 `lockMode: "overlap"`：只要有交集就锁（更狠）。
- 工作制可以在后台切 996 / 865 / 自定义，并逐项改上下班时间和工作日。

### 哪些身份不用自报家门

**好宝宝和 DAD&MUM 跳过「怎么称呼你」那一页**，直接落到日历（总共 5 步，不是 6 步）。

理由很直白：这两个身份牛马心里有数，还让人家自报家门就很怪。
名字走配置里的 `nameDefault`（默认「宝宝」「爸妈」），后台能改，也能把「问名号」重新打开。

实现上 `RoleConfig.askName` 决定步骤链：

```ts
const chain = asksName ? CHAIN : CHAIN.filter((s) => s !== 'name');
// 不问名号时 step 一开始就落在链子第一页，不会先闪一下名号页再跳走
const step: Step = rawStep === 'name' && !asksName ? (chain[0] ?? 'date') : rawStep;
```

### 日历：底色只说一件事

一个月里往往有十五六天约不上，所以**越少见的那个越该响**：

| 状态 | 怎么画 | 为什么 |
| --- | --- | --- |
| **能约** | 淡绿底 + 深绿数字 | 正面信号。少数派，让它跳出来 |
| **约不上** | 只压暗 + 划掉 + 🔒，**不给底色** | 多数派，安静下来 |
| **休息日** | 数字改成暖橙色，**不抢底色** | 底色已经用来表示「能不能约」了 |
| **今天** | 红色圆环 | 一眼找到今天 |
| **已选过** | 绿色 ✓ 角标 | |

底部图例四个都对上。

> **第一版做反了**：把「约不上」做成灰底圆片，实测糊成一堵灰墙，
> 反而把能约的那两天埋了。**底色是稀缺资源，要留给少数派。**

### 冷热小人：中午热、晚上冷

**热和冷是挂在不同时段上的**，不是都堆在中午：

| 时段 | 情绪 | 默认月份 |
| --- | --- | --- |
| 早上 | 无（只有「起不来」） | — |
| 中午 | 🥵 太热 | 6 / 7 / 8 月 |
| 晚上 | 🥶 太冷 | 12 / 1 / 2 月 |

按生活经验来的：**夏天最热是中午，冬天最冷是晚上**。

- 判定按**所选日期所在的月份**，两组月份列表都能在后台改。
- 不在对应列表里的月份（比如 9 月）那个时段就不显示小人。想让它一直有戏，把月份改宽即可。
- 代码里 `SlotCell.mood` 是**每格各自算**的，不是全表统一。

## 6. 地点

- 好友**自己填**；或点【你定吧】按钮把决定权交回后台。
- 文案：初态`你定吧`，开始躲之后变成`真的不再想想？`（两处都能在后台改）。
- 交互：
  1. 第一次点击 → 按钮**慢慢往旁边挪一小步（约 0.8 秒）就停下**，文案变成长的那句
  2. 此后 **3 秒内每点一下，它就再挪一步**（这期间的点击都不算数）
  3. 3 秒内不再点 → 它**自己慢慢挪回原位**
  4. 等它回到原位之后再点一次 → 认输，地点交给后台
- 不管怎么点，按钮**始终完整留在屏幕内**（每次挪步前都会按当前视口夹取范围）。
- 接受后：用户端地点字段显示`由你定`；后台详情里显示`【由你定】`。

## 8. 后台

- **需要登录**：口令登录（服务端鉴权，签发 token）。
- **列表要把主要内容摆出来**：**人物（昵称 + 身份）、时间、地点、留言**各占一行，
  一眼能看完「谁、什么时候、去哪、干嘛」。设备号这类排查信息不上主界面。
- **点某一条，详情就紧贴在那一条底下展开**（不是跑到列表最下面去），视觉上像同一张纸。
- 功能：
  - 审批列表（倒序）、按身份 / 状态筛选
  - 详情：人物 / 时间 / 地点 / 留言 + 原始 JSON（设备号只出现在原始 JSON 里）
  - 修改状态（待处理 / 已答应 / 已取消）、写**审批意见**、代填地点
  - 好友提的**见面要求**只读展示（那是好友的输入，后台不改）
  - **批量操作**：每条左边有勾选框，列表上方有**全选框**（支持半选状态，只作用于当前筛选结果），
    选中后出现「批量批准 / 批量驳回 / 批量删除」
  - 删除
  - 导出全部
- **系统配置页**（改完立即生效）：

  | 级别 | 配置项 |
  | --- | --- |
  | A | **总开关（接单 / 暂停营业）**；四个身份开关；工作制（996 / 865 / 自定义）；早中晚时段边界与**每一格是否可选**；可选日期范围 |
  | B | 四句关停文案；早上/中午弹窗文案；站名与副标题 |

## 8.5 回执与「什么时候能重填」

- 提交后进入**回执页**，显示「牛马正在骑马赶来的路上……」，**没有**「再填一份」或「换个身份」按钮。
- 回执页永远显示**牛马回复**（没写就显示「（牛马还没回复）」），好友自己提的要求也一并显示。
- 提示文案分三行排版，「请直接微信联系牛马」单独一行且**禁止折行**——重要的话被拆成两截会割裂。
- **被驳回**（cancelled）会进入单独一屏：显示「已驳回」+ 原时间 + **牛马回复（一定会展示）**，
  底下是「重新填一份」按钮，点了**回到入口页从选身份开始**。
- **重新填写会复用上一次的信息**：昵称、地点、留言自动带过来（页面会提示「上次填的帮你带过来了」）。
  **唯独不带你上次选的时间**——被驳回或已经过去的那几个时段，多半就是不能用的那几个，带过来反而容易误选。
  已经在填的草稿不会被覆盖。
- 好友能重新填写只有两种情况：
  1. 后台把这条**驳回**
  2. 约会日期**过了**——判定为「约会日之后的第 `reopenAfterDays` 天」（默认 1，即第二天就能重填；约会当天仍然锁定）；
     这种情况直接回到填写向导（身份不变）。

### 三种状态的文案（都可在后台改）

| 状态 | 主文案 | 副文案 | 小人 |
| --- | --- | --- | --- |
| 待审批 | 牛马在加班加点的审批中…… | 牛马正在骑马赶来的路上…… | 🥵 |
| 已通过 | 成了！ | 到时候见，别迟到。 | 🥳 |
| 已驳回 | 这次没约上（固定短句）+ 你们写的道歉 | — | 😭 带落泪动画 |

> 小人一律是 **emoji + CSS 动画**，不引外部 GIF：没有版权问题、体积为零、离线可用，
> 而且和前面「太热 / 太冷」的小人是同一套做法。要换成真人做的表情包，后面往
> `components.tsx` 的 `PUPPET_FACE` / `PUPPET_BITS` 里塞图就行。

### 见面要求（好友写的）

- 填写向导里单独一页：**「见面有什么小要求吗？」**，好友可以写一句，比如「带一朵鲜花」。
- **可以不填**，上限 60 字。
- 位置在「地点」之后、「留言」之前。
- 后台**只读展示**（列表里一行「要求」、详情里「好友的要求」），不提供编辑 ——
  那是好友的输入，写错了让他重填，不要后台悄悄改掉。
- 每个身份要不要有不同的说法 / 样式，后续再单独设计。

## 8.8 身份机制的边界（重要）

好友端**不登录**，身份靠浏览器 `localStorage` 里一个随机设备号。这决定了它的能力边界：

| 场景 | 结果 |
| --- | --- |
| 同一台设备、同一个浏览器再打开 | 认得出，显示回执 |
| **清了缓存 / 无痕模式 / 换浏览器 / 换手机** | **认不出**，回执看不到，可以再提交一条（重复） |
| 后台 | 一切照旧，记录都在，只是多了一条同名的 |

实测过（清掉 localStorage 再打开）：状态页会被重定向到填写页，等于一个全新的人。

**这是刻意接受的取舍**：换来的是好友不用注册、不用记密码、一个链接所有人通用。
要根治只有三条路，都要付代价：

| 方案 | 代价 |
| --- | --- |
| 每人一条专属链接 | 违背「一个链接发所有人」的初衷 |
| 加「档案号」找回 | 多一个概念；码丢了还得找后台要，而后台本来就能直接告诉他 |
| 加登录 | 好友根本不会为一次约饭注册 |

**当前的处理方式**：接受这个边界，但在回执上加了一句实话，把好友引到微信；
后台列表能直接看到同名同身份的两条，重复了用批量删除清掉。
如果哪天觉得重复太烦，再考虑加「档案号」。

## 8.9 暂停营业总开关

- 开关放在**后台最上面**（红头下面第一屏），是一条显眼的状态横条，**不在配置页里翻找**：

  | 状态 | 样子 | 按钮 |
  | --- | --- | --- |
  | 接单中 | 绿底 + 呼吸的绿点 + 大字「接单中」 | 暂停接单 |
  | 暂停营业 | 红底 + 红点 + 大字「暂停营业」 | 恢复接单 |

  这是「一键关店」的东西，随手就能点，所以走了单独的 `PUT /api/admin/site` 接口，
  **只改这一个字段**，不会把配置页里还没保存的改动一起覆盖掉。
  配置页原来那个小勾选框已经撤掉，改成跟着这条走。
- 关掉之后：好友端入口页和填写页都变成一屏**「小店拉闸关门」**：

  | 元素 | 动画 |
  | --- | --- |
  | 红色招牌「🐮 牛马小铺」 | — |
  | 营业灯 | 关门过程中由**绿转红** |
  | 卷帘门 | 从上往下落，落到底有轻微回弹 |
  | 帘面高光 | 落定后一道反光扫过 |
  | 「暂停营业」牌子 | 帘子落定后才挂出来，并轻轻左右晃 |

  纯 CSS 动画，没有外部素材；开了「减少动态效果」就自动静止。
- 牌子下面接你们配的那句话 + 「请直接微信联系牛马」。
- **已经交过单子的人仍然能看到回执**（走状态页），不至于被晾在外面。
- **但「重新开一单」的入口一律拦住**，包括被驳回的人：驳回页照常显示原因，
  但**不给「重新填一份」按钮**，换成一句「闭关中，等开门或者微信催他」。
  否则点下去只会撞到卷帘门，白跑一趟。
- 能被开单的路径全部堵死，一个不漏：

  | 入口 | 暂停营业时 |
  | --- | --- |
  | 入口页 `/` | 卷帘门整屏 |
  | 填写页 `/date/:role`（含书签、直链） | 卷帘门整屏 |
  | 驳回页的「重新填一份」 | 按钮不渲染 |
  | 已经填到一半时提交 | 后端 403 `SITE_CLOSED`，页面上给出提示 |
  | 直接打接口 | 后端 403 `SITE_CLOSED` |
- 后端也会拒绝新提交（403 `SITE_CLOSED`），不是只靠前端遮一下。

## 8.10 时间输入：可敲也可选（全站通病排查）

**规则：凡是跟时间有关的输入，都要「既能直接敲，也能用界面选」。** 逐项排查结果：

| 位置 | 实现 | 可敲 | 可选 |
| --- | --- | --- | --- |
| 后台 · 时段开始 / 结束 | `<input list="time-options">` | ✅ | ✅ 半小时一档 |
| 后台 · 工作制上班 / 下班 | 同上 | ✅ | ✅ |
| 后台 · 中午冷热**月份** | 12 个可点格子 + 输入框 | ✅ | ✅ 点格子 |
| 好友端 · 「几点」 | `<input list="time-hints">` | ✅ | ✅ 常用说法 |

「可选天数」「重填天数」这类是**计数**不是时间，就用普通数字输入框，不加下拉。

### 列表字段：全不选就是全不选

**用户改了的就按用户改的走**，不能因为「看起来像空值」就悄悄退回默认。
踩过两次同一个坑：

| 字段 | 全不选的含义 | 曾经的错误行为 |
| --- | --- | --- |
| 冷热月份 | 那个时段整年都不显示冷热小人 | 被改回默认的 `[6,7,8]` |
| 工作日的七天 | 这星期哪天都不上班（放假在家），所有时段都不锁 | 被改回默认的周一至周六 |

`normalizeConfig` 只在**字段整个缺失**时才退回默认；传了空数组就存空数组、按空的渲染。
两条路线各有断言钉住（`smoke.mjs` 的「月份全不选不会被改回默认」「工作日全不选不会被改回默认」）。

### 文本字段：清空就按默认走（**已定**）

文字类字段（站名、一句话、各条文案……）走的是另一套：**清空 → 用回默认值**。
理由是不想让好友端出现空白标题或空按钮。

> 这条和上面「列表字段全不选即全不选」看起来矛盾，其实是两种东西：
> **列表的「空」是一个有含义的选择**（哪个月、哪天），
> **文本的空更像「我没填」，用默认更合理**。两条都是明确的产品决定，不是漏掉的 bug。

### 两个刻意的例外

- **月份用的是「12 个格子 + 输入框」而不是 datalist**：它是**多值字段**（`6,7,8`），
  而 datalist 选中一项会**整串替换**，一点就把别的月份冲掉。所以要另配可点的格子。
- **日历的年 / 月仍然是 `<select>`**，不能敲。原因是**好友在微信里打开**：
  `<datalist>` 在微信 X5 内核上支持不稳，一旦不生效就退化成纯文本框，
  好友得手打「2026」「9」；而 `<select>` 在各家内核上都是原生滚轮选择器，稳。
  后台是桌面环境，用 datalist 没这个顾虑。

## 9. 数据与身份识别

- 好友填写**不需要登录**；用浏览器 `localStorage` 里的**设备号（随机 UUID）**作为弱身份。
- 同一个设备再次进入 → 显示自己的提交状态。
- **重复提交**：每次都新增一条记录，**不覆盖**历史。
- 状态展示持续到：约会日期已过 / 后台改了状态 / 后台删除。

系统配置页很长，保存按钮原来在最底下 —— 改完上面的字段要一路滑到底才能存，太别扭。

现在改成**钉在视口底部的保存条**：

| --- | --- |

## 9.4 「让你定」那个会躲的按钮

三个数字：

| | 值 | 说明 |
| --- | --- | --- |
| 躲避窗口 | **5 秒** | 这段内每点一下挪一步，到点**自己滑回原位**。原来是 3 秒，短到「刚躲完就回去了」，看不出往返 |
| 每步距离 | 96–180px | 随机方向 |
| 过渡 | 0.62s `cubic-bezier(0.22, 1, 0.36, 1)` | 丝滑的关键是曲线不是时长：起步快、收尾极缓 |

**活动范围（以它自己原来的位置为中心）**：

| 约束 | 值 | 为什么 |
| --- | --- | --- |
| 横向 | ±150px | 一开始只按视口夹取，结果它能飘到页面任意角落：盖住题目、压住分隔线、跑到「上一步」旁边，**看起来像从界面里掉出来了** |
| 纵向 | ±110px | 同上 |
| 视口内 | 12px 余量 | 别跑出去 |
| 手机底部 | 多留 88px | 底部工具栏会盖住视口下沿 |

四条同时成立；屏幕特别小时会夹出「下限比上限还大」，这时**退回原地不动**，不乱夹。

**每套皮都得动**：`[data-theme='dadmam'] * { transition-duration: 0s }` 这条
「公文不做花活」的规则**顺手把躲避按钮也压成瞬移了**，等于这个功能在公文皮上消失。
现在用更高的优先级把 `.btn-dodge` 救回来 —— 依然是匀速、不弹，符合公文皮的性子。

**「减少动态效果」的例外**：原来那段代码是 `if (reduceMotion) return` ——
一旦浏览器报告这个偏好，**按钮就彻底不动了，只换个字**，等于功能消失。
现在改成**照样躲，只是步子减半**（40–76px），过渡由 CSS 压到 0.2s。
理由是：这个偏好要挡的是大幅位移和视差，而**躲是这个按钮的全部意义**。

## 9.42 后台列表的排序与搜索

### 排序：打开后台第一眼就该看到「今天刚交、还没处理」的

| 优先级 | 什么样的 |
| --- | --- |
| 0 | **审批中 且 今天交的** |
| 1 | 审批中的 |
| 2 | 今天交的（已处理） |
| 3 | 其余 |

同档内按提交时间**倒序**。
列表上方写着一句「审批中和今天交上来的排在最前面」，今天的那几条还会打一个**黄色「今天」标**——
排序规则不该是黑盒，否则「怎么这个在上面」会一直让人困惑。

### 每个身份一套文案

**四个身份本来就是四种口气**，所以文案不再是全局一份，而是**每个身份一套**：

| 身份 | 口气 | 同一句「待审批」长这样 |
| --- | --- | --- |
| 好兄弟 | 直来直去，像半夜发微信 | 牛马在审，别急。 |
| 好姐妹 | 温柔，带语气词 | 我看看哦，稍等我一下～ |
| 好宝宝 | 撒娇、叠字 | 宝宝在看啦，等等宝宝嘛～ |
| DAD&MUM | 一本正经的公文口吻 | 申请已收悉，正在审阅中。 |

覆盖的字段有 11 条：早上弹窗、冷热两句、冻结 / 仅供观赏、待审批（主+副）、
已通过（主+副）、已驳回、关停弹窗标题。**站点关闭那句是全局的**，不分身份。

### 男生版 / 女生版：一键套用的语气预设

同一件事，男生和女生说出来的味儿确实不一样，所以每个身份都写了**两套**现成的
（见 `packages/shared/src/voices.ts`，4 个身份 × 2 版 × 11 条 = 88 条）。
后台每个身份的文案块顶上有一排 **「一键套用：男生版 / 女生版」**，
点一下整套换掉，换完还能逐条改。**套用不会自动保存**，保存条会变红等你确认。

出厂默认：好兄弟→男生版、好姐妹→女生版、好宝宝→女生版、DAD&MUM→男生版。

写这两套时守住两条：

1. **别腻**。「宝宝要睡觉觉的嘛～」这种过头了 —— **可爱不等于叠字多**。
2. **保住人设**。DAD&MUM 两版都还是公文腔，只是父亲版更短更硬、母亲版多两句关切
   （「记得避一避」「务必添衣」）。

实现：`RoleConfig.copies` 存身份的覆盖值，全局 `copies` 打底：

```ts
export function copiesFor(config: AppConfig, roleKey: RoleKey | undefined): CopiesConfig {
  const overrides = config.roles.find((r) => r.key === roleKey)?.copies;
  return { ...config.copies, ...overrides };
}
```

后台的文案编辑按身份**折成 5 个可折叠块**（四个身份 + 全站），
默认全收起 —— 不然 50 多个输入框铺一屏，谁也找不着。

### 按钮的悬浮说明

**每一个按钮都有 `title`**（实机核对：审批列表页 237 个、系统配置页 33 个，零遗漏）。

写的是「按下去会发生什么」，不是把按钮文字再抄一遍：

| 按钮 | 悬浮显示 |
| --- | --- |
| 暂停接单 | 关掉之后好友端只看到卷帘门；已交过单的人仍能看回执和驳回原因 |
| 批量删除 | 从库里删掉，好友那边也看不到了。删了就找不回来 |
| 复制回复话术 | 生成一段能直接粘进微信的回复，好友那边收不到通知 |
| 导出 CSV | 导出成表格，Excel / 飞书表格能直接打开 |
| 月价格子 | 3 月：点一下选中 / 取消 |

批量跑过一个静态检查（遍历每个 `<button` 往后看 9 行有没有 `title=`），
保证以后新增按钮时也漏不掉。

### 搜索框长什么样

**放大镜画在输入框里面**（不是旁边挂个图标）——这是「这里能搜」的通用语言，
不用配一句「在此搜索」的说明。输入框左侧留 32px 内边距给图标。

- 有内容时才出现 **×** 清空按钮（没内容时不占地方）
- 搜索框和刷新**编在同一组里**（`.search-group`），刷新紧贴搜索框右侧 ——
  以前搜索框 `flex: 1` 会把它顶到行的最右端，隔着一大段空白
- **刷新从文字按钮改成圆形箭头图标**，点下去图标会转一圈 ——
  转起来才说明「真的在刷新」，不是点了个寂寞

### 两种排序：按提交时间 / 按约会日期

| 排序 | 什么在前 |
| --- | --- |
| **按提交时间**（默认） | 审批中 + 今天交上来的 → 审批中的 → 今天交的 → 其余，同档按提交时间倒序 |
| **按约会日期** | **最近要赴的那场排最前**，已经过去的沉到最后 |

**牛马真正关心的是「下周末谁约了」**，所以「按约会日期」这一档是刚需 ——
光按提交时间排，隔着十几条才看见一个马上要赴的约。

配套一个**日期窗口筛选**：全部日期 / 今天要赴的 / 未来 7 天 / 未来 30 天。
一条申请可能同时约了好几天，所以判定是「**任意一天落在窗口里就算命中**」——
用「最早那天」判会漏掉后面几天。

列表上方那句排序说明会跟着当前模式变，不用猜现在是按什么排的。

### 审批意见支持换行

两个地方要一起改，只改一个都看不出效果：

1. **输入框**：`rows={3}` + CSS `field-sizing: content`（能跟着内容长高；
   不支持的浏览器退回固定三行，不影响用）
2. **显示处**：HTML 默认会把 `\n` 折叠成一个空格，所以回执和驳回页的
   `<dd>` 都要加 `white-space: pre-wrap` —— **牛马写了三行，好友看到的也必须是三行**

留言（好友填的那个大文本框）同样加了 `pre-wrap`。

### 搜索：一个框搜所有字段

留一个输入框，**关键字同时匹配**：

```
昵称 · 身份 · 状态 · 时间 · 地点 · 见面要求 · 留言 · 审批意见
```

**「时间」是可以搜的**：好友提的「9月14日 晚上」整句都在 `timeSummary` 里，
所以搜 `9月14`、`晚上`、`中午`、`凌晨三点` 都能命中。

在**客户端**筛（一次全量拉回来），敲一个字立刻出结果，不用来回打接口。
批量「全选」只作用于**筛出来的那些**，不会误选看不见的。

后台第三个标签页。把数据翻成一张自嘲的总结——这个应用既然走「牛马」这个调性，

## 9.5 排版原则：一句话尽量不从中间断开

展示内容时，**一句话能放一行就放一行**，真要断也不能断得难看。分四种情况：

| 情况 | 做法 | 例子 |
| --- | --- | --- |
| 短标签 / 短句 | `white-space: nowrap`，永远不断 | 状态徽章、字段名、时段名、日历星期、「请直接微信联系牛马」 |
| 列表里的一行 | 一行到底，超了打省略号；完整内容在展开 / 详情里看 | 后台审批列表的「时间 / 地点 / 要求 / 留言」 |
| 一个「日期 + 时段」 | 条目内部不断，要换行在**条目之间**换 | 回执里的时间胶囊 |
| 真正长的正文 | 允许换行，但用 `text-wrap: pretty / balance` 让断点均匀 | 留言、审批意见、身份卡那句话 |

全局还加了一句 `text-wrap: pretty`，避免最后一行只剩一两个字。

## 9.8 牛马本马（吉祥物）

「牛马」没有一个现成的 emoji（🐮 只有牛，🐴 只有马），所以**手绘了一只**：`NiumaMark`。

- **牛角**（骨白、短弯、位置上翘）+ **马耳**（土黄、长在两侧、比角矮）+ **马鬃**（额前一撮）+ **牛斑**
- 出没的地方：入口页红头徽标、后台抬头、卷帘门招牌「🐮 牛马小铺」、冻结时段的「牛马在上班」

**为什么手绘 SVG 而不是上网找图**：

| | 手绘 SVG | 网上找图 |
| --- | --- | --- |
| 版权 | 自己的 | 得逐个核实，出处还容易扯皮 |
| 体积 | 约 1KB，跟着 JS 走 | GIF/PNG 几十 KB 起，还要单独托管 |
| 清晰度 | 任意缩放不糊 | 小尺寸糊、大尺寸占位 |
| 离线 | 天然可用 | 多一个请求，挂了就空一块 |

风格也和现有的「太热 / 太冷 / 大哭 / 开心」小人一致（都是手绘感 + CSS 动画）。
以后你要是找到更满意的形象，替换 `components.tsx` 里的 `NiumaMark` 一处即可，全站都跟着换。

### 文字对比度：配色好看不等于看得清

有一轮好宝宝的文字被指出「看不清」，一量才发现**三项全不达标**：

| 好宝宝 | 改前 | 对比度 | 改后 | 对比度 |
| --- | --- | --- | --- | --- |
| 标题 `--red` | `#ff7fb4` | **2.29** ✗ | `#e04f8c` | 3.61 ✓ |
| 强调 `--red-deep` | `#ef5f9b` | **3.02** ✗ | `#b82b63` | 5.75 ✓ |
| 提示 `--muted` | `#b08fa0` | **2.81** ✗ | `#8a6a78` | 4.64 ✓ |

（门槛：大字 ≥3，正文 ≥4.5。）好姐妹的 `--muted` 也偏浅，3.40 → 4.77。

两条经验：

1. **同一份配色要分「填充」和「文字」两种用法看**。浅粉做背景很好看，
   做文字就糊。所以白字压色块的地方（按钮、选中日期）统一改用深一档的 `--red-deep`。
2. **对比度是可以量的**，别凭感觉。改配色时顺手算一下，
   `docs` 里记着这几个值，以后调色拿着比。

### 圆体偏轻：为什么宝宝的小字要单独加字重

有人指出宝宝页「总有一个字很淡」。一开始以为是标点回退了字体，**查下来不是**：

| 同一个字 | 幼圆墨量 | 雅黑墨量 |
| --- | --- | --- |
| 「要」 | 1103 像素 | 1418 像素 |
| 「？」 | 257 像素 | 308 像素 |

**幼圆整体比黑体轻约 22%** —— 大字号看不出来，12~13px 的小字就发虚。
而标点是笔画最少的字，**所以最先被看出来的是它**，才会觉得「总有一个字很淡」。

结论：**不是标点的问题，是整套字偏轻**。

### 修法走了两版弯路，最后是**换字体**

**第一版：列选择器名单加粗。** 漏了「第 X / N 步」「星期那一行」好几处 ——
**名单这东西永远列不全**，改完又被告知「还有几处也这样」。

**第二版：整页基准字重 600。** 覆盖是全覆盖了，但**合成加粗会把圆体糊成一团** ——
这是拿错误的办法解决正确的问题。

**最终版：换掉字体本身。**

| | 幼圆（原） | **站酷庆科黄油体**（现） |
| --- | --- | --- |
| 形象 | 圆润 | **一样圆润，还更可爱** |
| 笔画 | 偏轻，小字发虚 | 实心，小字清楚 |
| 授权 | 系统字体 | SIL OFL，可商用 |

- 原体 8.1 MB → **按界面用到的 981 个字符打子集，134 KB**
- `font-display: swap`：先拿系统字体顶上，字体到了再换，不让首屏白等
- 好友填的名字 / 留言里的生僻字**自动回退系统字体**（子集外的字）

> **教训**：字体「太轻」是**字体的属性**，不是字重的问题。
> 用 `font-weight` 去补字体的天生缺陷，只会得到一团糊的东西。

**两个仍然成立的小坑**（换字体也躲不掉）：

| 坑 | 说明 |
| --- | --- |
| `select / input / textarea` **不吃继承** | UA 样式把它们的 `font` 整体重置了 |
| 量下拉的字重要看 `select` 自己 | `<option>` 不继承、永远报 400（差点白改一轮） |

### 字体：为什么不用 Web 字体

中文 Web 字体**动辄十几 MB**，塞进微信链接是灾难（好友点开等着转圈）。
所以走**系统字体栈**——iOS / macOS / Windows 都自带这几套字，**零字节**：

| 主题 | 栈 | 为什么这么选 |
| --- | --- | --- |
| 好兄弟 | `Songti SC / STSong / SimSun` | 红头文件的标准标题字 |
| 好姐妹 | `Kaiti SC / STKaiti / KaiTi` | 楷体有笔锋，秀气 |
| 好宝宝 | `Yuanti SC / YouYuan` | 圆体笔画端点都是圆的，天然显软 |
| DAD&MUM | `FangSong / STFangsong / FangSong_GB2312` | **GB/T 9704 规定党政机关公文正文就用仿宋_GB2312** |

> **代价**：Android 上自带中文字体只有思源黑体，四套字体栈会退化成同一个。
> 那时候靠**字重、字距、字号**的变化撑着——好宝宝加粗、DAD&MUM 放大到 16px。
> 要彻底解决只能上 Web 字体，但那十几 MB 的代价对「微信里点开一条链接」来说不值。

### 怎么实现的

1. **配色走 CSS 变量**：`[data-theme='sister'] { --red: …; --line: … }`——
   既有那几百条规则不用动，自动跟着换色。
2. **方圆走形状变量**：`--r-sheet / --r-card / --r-field / --r-btn`，
   各组件只认变量，具体数值由主题给。
3. **装饰单独写**：背景纹理、珠链分隔线、爱心角标这些没法靠变量，逐个主题写。
4. **入口卡的元素级匹配**：卡片是「卡自己带 `data-theme`」，
   而页面是「`<html>` 带 `data-theme`」，两种写法都要匹配（CSS 里成对出现）。

> **两个坑**（都踩过）：
> - CSS **同优先级下后写的赢**。主题块在文件开头，被后面写死的 `letter-spacing` / `border-radius`
>   全面压制。解法：给主题规则加 `[data-theme]` 提权，并在**文件最末尾**做一次形状收口。
> - `usePageTheme()` **必须在任何提前 `return` 之前调用**，否则钩子数量时多时少，
>   违反 Hooks 规则 —— 而且症状是「主题静默不生效」，不会报错，很难查。

## 路由：有申请就先看结果

**问题**：好友被驳回后点同一个身份，直接进了一张空表单 ——
他**看不到牛马写的意见**，只会以为自己的申请凭空没了。

**规则**（三条，缺一不可）：

| 进哪 | 有申请时 | 没申请时 |
| --- | --- | --- |
| `/`（点链接进来） | 送去自己的状态页 | 显示身份卡 |
| `/date/<身份>` | 送去状态页（先看结果） | 表单 |
| `/date/<身份>?again=1` | 表单（「重新填一份」走这个） | 表单 |

**⚠️ 两条重定向的条件必须严格互补**：

```
填写页 → 状态页   当：  驳回  ||  单子还有效
状态页 → 填写页   当： !还有效 && !驳回
```

写成「只要有过单子就跳状态页」会**死循环** ——
状态页会说「约会日过了，去重填」，填写页又把人送回来。
（第一版就是这么写的，推到条件的时候才看出来。）

**「换个身份」**走 `/?pick=1`。没有这个逃生口，入口页会自动跳走、
用户点回来又被跳走，观感像卡死。

## 认浏览器不认账号：代价要讲清楚

好友端**不登录**（这是刻意的：不用注册、不用下载、点开就能填）。
代价是**认人靠浏览器里存的随机编号**，而那个编号会没：

| 什么时候会没 |
| --- |
| 换了浏览器 / 换了手机 |
| 清了浏览器缓存（微信「清理缓存」也算） |
| 无痕 / 隐私模式 |
| 浏览器禁用了网站存储 |

**产品决定：与其让好友一脸懵，不如正面讲清楚。**

所以有了「我的申请」页（`/mine`）：找不到时明确列出上面这几种情况，
说明「不用注册」就是这个代价，**并强调「你交过的申请，牛马那边一直都留着」**。

最后那句最重要 —— 好友「明明交过却找不到」时，
最怕的是以为**没交成功**或者**数据丢了**。得先把这个恐惧解掉，再谈别的。

## 一个真实的手机端事故

好友反馈「首页能进，选完角色就白屏」。

**根因**：`getDeviceId()` 里读 `localStorage` 没兜住异常。
手机浏览器（微信内置 / 无痕 / 禁用存储）会让它**直接抛异常**，
一抛 → React 整棵树卸载 → 整页白屏。

**为什么这个特征这么典型**：入口页不碰存储，所以能开；
一进填写页就要读设备号，就崩。**「哪一页白」本身就是最强的线索。**

**教训**：

1. **浏览器存储不是「一定会成功」的 API**，该包 try/catch 的地方要包
2. **`crypto.randomUUID` 也不是到处都有**（iOS 15.4 以下的 Safari / 微信内置浏览器）
3. **白屏是最难排查的失败形态** —— 所以后来还加了错误边界和静态兜底，
   宁可显示一句人话，也不要一片空白
4. **能复现的 bug 才算修好的 bug**：用无头浏览器模拟「localStorage 抛异常」，
   修之前 1 个元素、修之后 112 个元素，一眼就能验证
